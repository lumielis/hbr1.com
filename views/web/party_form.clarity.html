Both bands pointed at the same legacy URL (`?part=edit&party_id=new` and `?part=edit&party_id=N`); here they are two routes over one template, `/party/new` and `/party/{id}/edit`. The layout is the legacy one, section by section, because the page has to sit in the same 583 px frame as the calendar: - one SUBMENU band above and below the well, both reading GO_BACK. The legacy link was `javascript:history.back();`, which is kept: the form is reached from two different pages and neither is the "right" one to return to. - the well starts with a `

It is the one page that never got updated. Two notes on the controls themselves: *Nothing is preselected on a new form.* The legacy `` and `` marked an option `selected` only when the stored row already held that value, so a fresh form left the browser to pick - "Indoor" for the type, and **Afghanistan** for the country, because that select is ordered by name. A two-digit year is read back as 20xx. The password confirmation is shown on both forms.
